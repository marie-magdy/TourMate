# 🧭 TourMate — AI-Powered Egyptian Tourism App

TourMate is a full-stack mobile tourism application designed to help travelers explore Egypt intelligently. It combines a React Native (Expo) frontend with a Node.js backend, a Python-based AI recommendation engine, and a computer vision service — all working together to deliver personalized itineraries, landmark recognition, voice-driven AI assistance, and a tier-gated Pro subscription.

## ✨ Features

### 🗺️ Smart Itinerary Planner
- Multi-day trip planning with city, budget (EGP), date range, and per-day hours
- AI-driven attraction selection using a 2D knapsack (time × budget) algorithm
- Adaptive per-day budget splitting based on selected spots and city-level pricing
- Liked spots are guaranteed to appear in the itinerary; remaining time is filled by recommendation score
- Geo-clustering keeps each day's stops geographically tight to minimize travel
- Plan Coach — conversational edits to a live itinerary with preview-then-apply

### 🔍 Attraction Discovery
- Browse popular attractions across Egyptian cities
- Filter by city and category (historical, nature, food, beach, shopping, museum, etc.)
- Full-text search across name, city, description, and categories
- Filtered Results screen for refined discovery flows
- Nearest attractions to the user's current city
- Detailed attraction pages with images, rating, price, opening hours, and map pin

### 🤖 TourMate AI Chat Assistant
- Powered by **LLaMA 3.3 70B Versatile** via the Groq API
- Egypt-tuned system prompt covering 20+ landmark types
- Voice input via Groq Whisper Large v3 transcription
- Voice output via Groq Orpheus TTS (multi-chunk WAV streams)
- Dedicated `VoiceScreen` for hands-free voice chat
- Free tier: **15 messages**, Pro tier: unlimited

### 🎙️ AI Audio Guide
- AI-generated narration for any attraction in English or Arabic
- Script is generated by LLaMA 3.3 via Groq, then converted to audio by Orpheus TTS
- Long scripts are split into chunks ≤ 190 characters and combined into a single WAV stream
- Available directly from the attraction detail screen

### 📸 Landmark Recognition (Computer Vision)
- Take or upload a photo to identify Egyptian landmarks and museum artifacts
- Two TensorFlow Lite models running on the Flask CV service:
  - **Outdoor landmarks** — 11 major outdoor sites (Pyramids, Sphinx, Citadel of Qaitbay, Bibliotheca Alexandrina, etc.)
  - **Museum artifacts** — Egyptian museum artifacts
- Confidence threshold of 60% before a result is returned
- On recognition, the full attraction detail is fetched from the database and displayed
- **Gated by Pro subscription** — free tier sees the upgrade prompt

### 💎 TourMate Pro Subscription
- Tiered feature model with a `user_feature_flags` table and an `assertFeatureAccess()` middleware
- **Free tier:** 15 AI chat messages, 5 Plan Coach edits, no voice chat, no CV recognition, no AR mode
- **Pro tier (99 EGP one-off):** unlimited chat, unlimited Plan Coach, voice chat, CV recognition, AR / smart-glasses mode
- Simulated payment flow at `/api/subscription/upgrade`
- Admin override available from the dashboard
- `ProUpgradeModal` component drives the upsell across screens

### ⭐ Favorites & Saved Plans
- Save any attraction to a personal favorites list
- Save completed itineraries with rename / delete / open-back-up
- `bookingStore` (Zustand) keeps hotel and flight selections in memory across screens

### 🏆 Rewards & Points System
- Users earn points for engagement actions
- Walk-to-earn points via GPS-verified walking sessions
- Admins can manually award bonus points
- Points can be redeemed for rewards listed in the rewards catalog
- Full points history per user

### 🔐 Authentication
- Email/password registration and login with bcrypt cost-12 hashing
- Google OAuth sign-in
- JWT-based sessions (7-day expiry)
- Change password, edit profile, delete account
- Role-based access: `user` and `admin`
- Voice-feature unlock via points (alternative to Pro upgrade)

### 👑 Admin Dashboard
- Platform stats: total users, attractions, favorites, points distributed, top attractions by favorites
- Manage users: view, delete, change roles, manually award points
- Feature flag controls: enable/disable voice chat and grant Pro-tier features per user
- Manage attractions: full CRUD with image upload, category assignment, and city selection
- Dedicated `add-attraction` screen with field validation

### 🗺️ Interactive Map
- Map view of all attractions with city-filtered pins (React Native Maps)
- Web-compatible alternative map view (`map.web.tsx`)
- Tappable pins open an attraction bottom sheet
- GPS-denied graceful fallback to Alexandria

### 🌍 Localization
- English, Arabic, French, and German translations
- Full i18n string coverage for all screens
- Language preference saved per user
- Arabic flips to RTL layout

### 🎨 Onboarding & Splash
- Onboarding screen with illustrated slides (native and web variants)
- Animated splash screen with token-based routing (admin / user / onboarding / login fallback)

### 🔔 Notifications
- Local notification scheduling via `expo-notifications` (15-minute pre-activity reminders)

Production deployment runs the three backend services in Docker on a single Azure VM (UAE North region) behind an Nginx reverse proxy, with auto-restart on container failure. The Expo app talks only to the Node API; the Node API is the gateway to every internal service and external dependency.

## 🚀 Getting Started

### Prerequisites

- **Node.js** v18+ and npm
- **Python** 3.10+
- **PostgreSQL** database (local or hosted, e.g. Supabase, Neon)
- **Expo CLI** (`npm install -g expo-cli`)
- **Groq API Key** (free at [console.groq.com](https://console.groq.com))
- A physical device or emulator for React Native

---

### Environment Variables

#### `backend/.env`
```env
PORT=3000
DATABASE_URL=postgresql://user:password@host:5432/dbname
JWT_SECRET=your_jwt_secret_here
GROQ_API_KEY=your_groq_api_key_here
BACKEND_IP=192.168.x.x          # Local IP for image URL generation
API_KEY=your_cv_service_key     # Shared secret for CV service
```

#### `recommendation_service/.env`
```env
DATABASE_URL=postgresql://user:password@host:5432/dbname
```

#### `cv_service/.env`
```env
API_KEY=your_cv_service_key     # Must match backend API_KEY
```

#### `frontend/.env`
```env
EXPO_PUBLIC_API_URL=192.168.x.x   # IP or hostname of the backend (port 3000 assumed)
EXPO_PUBLIC_EXCHANGE_API_KEY=...  # ExchangeRate-API key for currency conversion
EXPO_PUBLIC_GOOGLE_PLACES_KEY=... # Google Places key for ride-share fare estimates
```

---

### Running the Backend

```bash
cd backend
npm install
npm run dev       # Development with hot reload (node --watch)
# or
npm start         # Production
```

The server starts on **port 3000**, connects to PostgreSQL, and runs the Pro-subscription schema migration on startup. The `/api/recognition/analyze` route is gated by the Pro feature flag.

---

### Running the Recommendation Service

```bash
cd recommendation_service
pip install -r requirements.txt
python app.py
```

Runs on **port 5002**. Loads attraction data from PostgreSQL on startup and builds the feature matrix for cosine-similarity scoring.

---

### Running the CV Service

```bash
cd cv_service
pip install -r requirements.txt
py -3.9 app.py
```

Runs on **port 5001**. Loads both TFLite models into memory on startup. Requires an `API_KEY` header on all recognition requests.

---

### Running the Frontend

```bash
cd frontend
npm install
npx expo start
```

Scan the QR code with Expo Go, or run on a connected emulator. For web:

```bash
npx expo start --web
```

## 🤖 Services Overview

### Recommendation Engine (`recommendation_service/`)

A Python Flask API exposing four endpoints. The core logic (`reccomender_v2.py`) implements:

- **Feature matrix:** each attraction is encoded as a category vector covering `ancient`, `beach`, `museum`, `historical`, etc.
- **Cosine similarity scoring:** user interest vector vs. attraction category vector (60% weight)
- **Popularity and rating bonuses** (20% + 10% weight)
- **Price score** relative to available budget (10% weight)
- **Liked spot guarantee:** user-selected spots are always included; remaining slots are filled by recommendation score
- **Geo-clustering:** attractions grouped by location per day using city-tuned radius limits
- **2D knapsack (DP):** discretized time × budget grid to find the optimal set of fill attractions
- **Taxi cost estimation:** city-specific base fare + per-km rates rolled into day budgets
- **Adaptive budget splitting:** per-day fractions computed from the price distribution of liked spots
- **OSRM-based timing:** real walking / driving durations between stops

Supports Cairo, Alexandria, Luxor, Aswan, Hurghada, Sharm El Sheikh, Dahab, Marsa Matrouh, Siwa, and El Gouna.

### Computer Vision Service (`cv_service/`)

A Python Flask API that runs two TensorFlow Lite image classification models:

- **Outdoor Landmarks** (`outdoor_landmarks.tflite`, ~9.1 MB) — 11 outdoor sites including the Great Pyramids, Sphinx, Bibliotheca Alexandrina, Montaza Palace, Citadel of Qaitbay, Stanley Bridge, and more.
- **Museum Artifacts** (`museum_artifacts.tflite`, ~9.8 MB) — 7 artifact classes.

Images are resized to 224×224 and normalized before inference. Results with confidence below 0.60 are rejected. The service is protected by a shared API key passed as an `x-api-key` header.

### Backend Services (`backend/src/services/`)

- **`userFeatures.js`** — Pro / Free tier gating. Owns the `user_feature_flags` schema migration (runs on server start), the `assertFeatureAccess()` middleware used by AI / CV routes, and the `upgradeUserToPro()` helper that drives the simulated payment flow.
- **`planCoach.js`** — Plan Coach edit engine. Converts a chat message + a live itinerary into a structured edit operation (drop stop, retime day, swap attraction, add day, etc.), validates against open hours and budget, and returns a preview the user can apply or discard.

## 🗄️ Database Schema

Key tables in PostgreSQL:

| Table | Description |
|---|---|
| `users` | User accounts (id, username, email, password, role, avatar_url) |
| `cities` | Egyptian cities (city_id, name) |
| `attractions` | Attractions (id, attraction_id, name, city_id, description, rating, price_from, opening_hours, is_popular, latitude, longitude, model_label) |
| `attraction_images` | Multiple images per attraction with primary flag |
| `attraction_categories` | Join table linking attractions to categories |
| `categories` | Category definitions |
| `favorites` | User-attraction favorites |
| `hotels` | Hotel listings per city |
| `user_points` | Points balance and total earned per user |
| `points_history` | Audit log of all point transactions |
| `rewards` | Reward catalog items with `points_required` |
| `saved_plans` | Saved itinerary plans (JSONB for itinerary, interests, spot_ids, flight_details, hotel_details) |
| `user_feature_flags` | Per-user feature toggles: `is_pro`, `chat_count`, `plan_coach_count`, `voice_chat_enabled`, `expires_at` |

> **ID convention:** the recommendation engine uses `attraction_id` (e.g. `ATT001`) from the attractions table, while the main browse flow uses the integer serial `id`. Both are supported in the `/api/attractions/:id` route.

> The `user_feature_flags` table is auto-created at server startup via `ensureProSchema()` if it doesn't exist.

## 🧪 Testing

The repo ships with three test projects totalling **475+ automated tests** that run in ~37 seconds end-to-end.

| Project | Framework | Tests | Wall-clock |
|---|---|---:|---|
| **Backend** (`backend/tests/`) | Jest 29 (ESM) + supertest 7 | **245** | ~5 s |
| **Frontend** (`frontend/tests/`) | jest-expo + @testing-library/react-native | **219** | ~24 s |
| **CV service** (`cv_service/tests/`) | pytest 9 + Flask test_client | **15** | ~8 s |

All I/O is mocked at the boundary — there is no live database, network, or external API during tests:

- `pg.Pool` is replaced via `jest.unstable_mockModule('../src/db.js', …)`
- `bcrypt`, `jsonwebtoken`, `node-fetch`, and `global.fetch` are mocked per file
- `tf.lite.Interpreter` is patched in pytest fixtures with a configurable fake output

A custom timing reporter prints a per-file table at the end of every run (see `backend/tests/timing-reporter.cjs` and `frontend/tests/timing-reporter.js`). A separate reproducible benchmark script lives at `backend/tests/benchmark.test.js` and runs supertest with 200 iterations per endpoint plus a concurrent-user load test from 10 → 500 users.

Run everything:

```bash
# Backend
cd backend && npm test

# Frontend
cd frontend && npm test

# CV service
cd cv_service && python -m pytest tests/
```

Run the perf benchmark on demand:

```bash
cd backend && npm test -- --testPathPattern=benchmark
```

Sample measured numbers (mocked DB, supertest, 200 iterations / endpoint):

| Endpoint | Avg | p95 |
|---|---:|---:|
| `GET /attractions` | 3.68 ms | 5.76 ms |
| `POST /auth/login` | 4.18 ms | 6.31 ms |
| `POST /plans` | 3.49 ms | 5.21 ms |
| `POST /recognition/analyze` | 5.14 ms | 6.99 ms |
| `POST /ai/chat` | 3.34 ms | 4.48 ms |
| `GET /attractions/nearest` | 3.49 ms | 4.68 ms |

Numbers characterize the application-layer overhead; live PostgreSQL adds 1–10 ms per query and bcrypt cost-12 adds ~250 ms to `/auth/login`.
