## File Purposes & Relationships

### Entry Point
```
npm run dev  →  src/index.js  →  Express app setup  →  routes/auth.js
```

### Data Flow for Registration
```
POST /api/auth/register
     ↓
controllers/authController.js::register()
     ↓
services/authService.js::registerUser()
     ├─ validateRegistrationInput()
     ├─ hashPassword() [bcrypt]
     ├─ generateNextUserId() [models/User.js]
     ├─ getNearestCity() [utils/geolocation.js]
     └─ INSERT into database
```

### Data Flow for Login
```
POST /api/auth/login
     ↓
controllers/authController.js::login()
     ↓
services/authService.js::findUserByEmail()
     ├─ Find user in DB
     ├─ comparePasswords() [bcrypt]
     └─ Generate JWT token
```

### Data Flow for Protected Routes
```
PUT /api/auth/location (+ Authorization header)
     ↓
middleware/auth.js::authenticateToken()
     ├─ Extract JWT from header
     ├─ Verify signature
     └─ Attach user_id to req.user
     ↓
controllers/authController.js::updateLocation()
     ↓
services/authService.js::updateUserLocation()
     ├─ getNearestCity() [utils/geolocation.js]
     └─ UPDATE database
```

## Key Files Explained

### 1. `src/index.js`
**What**: Main application entry point  
**Does**: Sets up Express server, middleware, and routes  
**Routes**: `/api/auth` endpoints  
**Listen**: Port from .env (default 3000)

### 2. `src/routes/auth.js`
**What**: Authentication route definitions  
**Does**: Maps HTTP methods to controller functions  
**Uses**: authController functions  
**Middleware**: authenticateToken for protected routes

### 3. `controllers/authController.js`
**What**: HTTP request/response handlers  
**Does**: 
- Extracts data from request
- Calls service functions
- Returns formatted responses
**Handles**: register, login, updateLocation

### 4. `services/authService.js`
**What**: Business logic layer  
**Does**:
- Input validation
- Password hashing/comparison
- User ID generation
- Database operations
- City detection

### 5. `models/User.js`
**What**: User data model  
**Does**:
- Defines Sequelize model (currently using raw SQL)
- Generates sequential user IDs (USR001, USR002, etc.)
- Queries highest existing ID
- Returns formatted next ID

### 6. `utils/geolocation.js`
**What**: Location utilities  
**Does**:
- Stores Egyptian city coordinates
- Calculates Haversine distance
- Finds nearest city
- Validates coordinates

### 7. `middleware/auth.js`
**What**: JWT authentication middleware  
**Does**:
- Extracts token from Authorization header
- Verifies JWT signature
- Checks token expiration
- Attaches user_id to request

### 8. `config/database.js`
**What**: Database configuration  
**Does**: Connects to PostgreSQL via Sequelize  
**Uses**: DATABASE_URL from .env

### 9. `src/db.js`
**What**: PostgreSQL connection pool  
**Does**: Raw SQL query execution  
**Used by**: Services for database operations

## Database Tables & Relationships

### Created by `init.js`

#### users

Columns:
- user_id (VARCHAR(10)) - PK - Sequential: USR001, USR002, etc.
- name (VARCHAR)
- email (VARCHAR) - UNIQUE
- password (VARCHAR) - Bcrypt hashed

- created_at (TIMESTAMP)
- updated_at (TIMESTAMP)

Indexes:
- PRIMARY KEY on user_id
- UNIQUE on email
- INDEX on current_city

## How to Add New Features

### Add a New Route
1. Create handler in `controllers/` (e.g., `userController.js`)
2. Create service in `services/` (e.g., `userService.js`)
3. Add route in `src/routes/` (e.g., `src/routes/users.js`)
4. Import route in `src/index.js`
5. Test using API_TESTING.md examples

### Add a Database Table
1. Create table in `init.js` (in createTables function)
2. Add seed data if needed
3. Run `npm run init-db`
4. Create model if using ORM features
5. Update ARCHITECTURE.md

### Add a Utility Function
1. Create/update file in `utils/`
2. Export function as default
3. Import in service where needed
4. Test thoroughly
